Method: canonical-v2 and fixed requests; measured baselines and candidates require at least ten samples and CV at most five percent. Speed comparisons use matching protocols. Native short-prefill v4 uses five-request arithmetic-mean blocks, ten measured blocks per binary; block CV is the quality statistic and raw-request CV is retained separately. No trimming.

decode_at_10k remains report-only. First-request prefill work and the full automated release model are deferred under the lean protocol.

Known limitations:
- Native Windows graph-instantiation recovery was not re-injected for the selected rung. Actual native allocation recovery covers the twelve-gigabyte OFF profile; the sixteen-gigabyte contract has its separate direct owner-accepted inherited coverage limitation, explicitly not a native allocation recovery PASS. Linux/WSL graph evidence and actual source equivalence are retained.
- The first request after a context change can show lower prefill throughput. The missing per-depth warmup investigation and a runtime fix are deferred.
- Windows Ampere and Ada packages are build-only until matching hardware receipts exist. WSL throughput is measured under WSL; it is not a bare-metal Linux throughput claim.
- The previous source archive omitted the model implementation directory and did not build standalone. Complete source and a clean-extract build are required for this draft.
- Inherited project library origins preserve original sources and recorded recipes. The original Linux chunk-wrapper compiler invocation was not recorded; its retained source mapping and static binary identity are reported separately from newly compiled stages.
- Native Windows SM120 sixteen-gigabyte allocation recovery is an inherited, un-reinjected coverage limitation explicitly accepted by Sean. No native allocation recovery PASS is claimed for that contract; actual Linux/WSL and native smaller-profile evidence and the native graph limitation remain recorded.
- Inherited Windows Ampere and Ada GDN kernels retain exact published bytes, original PTX/source and target-SASS identity audits. They are project-generated retained origins, not newly compiled stages or relabeled vendor artifacts.
- Original full-suite Windows Mirai mismatches are preserved: twelve-gigabyte CLI-24 and CLI-40 and sixteen-gigabyte CLI-39 each passed unchanged v0.1 and failed the candidate. Their separate isolated pass rates and standing-rule classifications do not replace those original outcomes.
