Windows SM120 source and build inputs

The release source-input ZIP contains the full prepared Windows control-source
tree and the exact measured experiment-source layout. Its SHA-256 is published
with the runtime ZIP. The flat experiment source/ and bridge/ layout preserves
the bridge's relative startup-header include. This repository directory mirrors
the changed files and recorded commands; it does not replace the full base tree.

Toolchain used: nvcc13.0.88, runtime13.0.96, cuBLAS13.1.1.3,
MSVC19.44.35228, CMake4.4.3 and Ninja. NVIDIA-REDISTRIBUTABLES.json in the source
archive pins the official13.0.3 components and download hashes. The source and
NVIDIA notices are included in the runtime archive.

RECORDED-CONTROL-BUILD.cmd is the successful full control build, including the
exact CMake options, architecture flags and companion compilation. The recorded
experiment build compiles the two changed CUDA translation units, preserves the
control object set, and relinks the backend. RECORDED-BRIDGE-FINISH.py and
BUILD-PROVENANCE.json record the successful bridge build and flags.

These are historical, path-specific build records. On a fresh build machine,
map their control source, build, compiler, bridge and experiment paths to the
extracted input directories. Preserve the options and model-independent source
identities; do not substitute an upstream checkout. Do not run the historical
scripts against an existing champion directory: they intentionally refuse
existing experiment packages, and their absolute paths are visible in the files.

The changed source files implement structural guards before impossible fusion
lookups and owned first-use snapshots for selected stable feature flags.
Attestation/test controls stay dynamic. Restart to change a snapshotted flag.
The shipped K256 instructions match the CUDA13.0/Linux control exactly.

The certificate qualifies the archived, measured binary hashes. A rebuilt PE
may differ in metadata or layout and is not certified merely because these
sources were used. Verify its active DLLs, kernel routes, golden outputs and the
full original performance/stability/capacity/quality/vision gates before claiming
hardware qualification for the rebuilt artifact.
