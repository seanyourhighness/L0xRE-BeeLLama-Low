## Source bundle and reproducibility limits

Source packet471 captures949 recorded Linux project source/header inputs and512 dependency receipts, each against its recorded hash. The full source bundle additionally retains host source trees, the compact/prefetch overlays, portable Windows CUDA inputs, architecture corrections, companion source, generated-kernel references, build recipes and toolchain records. `SOURCE-FILES.json` and original manifests identify inputs and modifications. Historical absolute paths in build recipes require rebasing to the retained directories and installed SDKs. Toolchains/SDK binaries, model weights and optional control vectors are not bundled. Several snapshots lack complete Git metadata; no source commit or bit-for-bit rebuild guarantee is invented.

During earlier dependency reconstruction, GNUobjcopy inspection calls rewrote five original object ELF containers. They were not byte-restored. Qualified linked runtime libraries retained their recorded hashes. Receipt427 independently matched all eight reconstructed device-code inputs to unchanged qualified linked libraries;430 retains original/current container hashes and explicitly rebinds the dependency evidence. Receipts424/427/430 and the incident record accompany the source/evidence packet. This is source/dependency evidence, not hardware certification.
